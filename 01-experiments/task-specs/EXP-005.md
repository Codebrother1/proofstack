# EXP-005 — Agent Handoff: Repository Review to Verification Plan

Status: Ready after GitHub repository exists

## Task

Cursor inspects EXP-001 and creates a structured handoff. Grok Bot continues from that handoff and creates a verification plan without changing code.

## The task passes only if

1. Cursor's handoff contains objective, current state, completed work, incomplete work, files to inspect, known failures, decisions, do-not-change constraints, next action, and definition of done.
2. Grok Bot identifies all six frozen EXP-001 acceptance criteria from the handoff or referenced task spec.
3. Grok Bot produces a criterion-by-criterion verification plan at `03-evidence/EXP-005/attempt-01/verification-plan.md`.
4. Every planned check names the concrete evidence needed and a PASS/FAIL/UNVERIFIED rule.
5. Grok Bot does not modify source code or tests.
6. Any missing handoff information is labeled missing rather than invented.

## Cursor instruction

```text
Inspect EXP-001 and its current repository state. Create 03-evidence/EXP-005/attempt-01/cursor-handoff.md using the exact handoff headings in HANDOFF.md. Preserve the six frozen acceptance criteria by reference or verbatim. Do not change source code or tests.
```

## Grok Bot instruction

```text
Continue from 03-evidence/EXP-005/attempt-01/cursor-handoff.md. Create verification-plan.md in the same folder. For every frozen EXP-001 acceptance criterion, name the concrete check, required evidence, and the rule for PASS, FAIL, or UNVERIFIED. Do not modify source code or tests. If context is missing, label it MISSING CONTEXT rather than guessing.
```
