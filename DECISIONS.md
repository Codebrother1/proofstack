# Decision Log

## D-001 — One project, four layers

**Decision:** Keep one through-line: question → benchmark → ProofStack protocol → event build.

**Why:** The talk, dataset, giveaway, and open build should reinforce one another.

## D-002 — Dataset size

**Decision:** 20 minimum, 24 target, 30 stretch.

**Quality gate:** Stop adding runs if acceptance criteria, evidence, or verification become sloppy.

## D-003 — Category allocation

**Decision:** Repo/code, browser/UI, and handoff/multi-agent are core. Routine, cross-tool, and approval/risk are supporting categories.

## D-004 — Ground truth

**Decision:** Human inspection and objective evidence determine the benchmark outcome. An agent verifier is a measured participant, not the final authority.

## D-005 — ProofStack scope before the event

**Decision:** ProofStack v0 is a protocol: task spec, acceptance criteria, execution record, verification, evidence packet, classification, and report card. Software is optional until the benchmark reveals what should be automated.

## D-006 — Project tools

**Decision:** Use GitHub for artifacts/history, the workbook for experiment data, and Linear only for milestones and next physical actions.

## D-007 — Talk framing

**Decision:** Frame the work as pro-deployment and tool-agnostic. Open with a genuine autonomous success, then show the trust gap and the evidence workflow.

## D-008 — Credential policy

**Decision:** No personal, client, production, billing-authority, or stranger-provided credentials in demo systems. Use controlled public resources, local fixtures, or scoped burner accounts.
