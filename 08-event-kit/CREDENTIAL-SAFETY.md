# Credential Safety

- Do not store login emails, passwords, API keys, tokens, or recovery information in this repository.
- Do not give a demo agent personal, client, production, financial, or billing-authority credentials.
- Do not accept another attendee's credentials for a live demo.
- Prefer public data, local fixtures, and scoped burner accounts.
- Require explicit approval before outbound messages, publishing, account changes, purchases, deletion, or other consequential actions.
- Rotate and remove demo credentials after the event.

Useful stage line:

> The point of this project is knowing what deserves trust. I won't weaken the credential boundary just to make a demo more exciting.
